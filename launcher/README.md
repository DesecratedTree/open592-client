# open592 launcher

A small cross-platform launcher for the open592 client, styled after the 2010
RuneScape launcher: an update log with a banner, a media tab, a community panel
placeholder and a settings pane.

The shell is Rust + Tauri 2 (WebView2 on Windows, WebKitGTK on Linux, WKWebView
on macOS). The front-end is plain HTML/CSS/JS served from `ui/` — there is no
Node or bundler step.

## Requirements

- Rust 1.90 or newer (`cargo test` is enough to check the backend). Tauri
  2.12.5, which `Cargo.lock` pins, requires 1.90.
- Tauri 2's platform prerequisites:
  - **Windows**: WebView2 runtime (installed on Windows 10/11) and the MSVC
    build tools. Git's `usr/bin/link.exe` can shadow MSVC's linker; if the link
    step fails, put the Visual Studio bin folder first on `PATH`.
  - **macOS**: Xcode command line tools.
  - **Linux**: `libwebkit2gtk-4.1-dev`, `libgtk-3-dev`,
    `libayatana-appindicator3-dev` and `librsvg2-dev` (Debian/Ubuntu names).
- A Java 8 runtime for the client itself. The launcher looks in `JAVA_HOME`,
  then `PATH`, then (macOS) `/usr/libexec/java_home`, and every one of those can
  be overridden in the settings pane.

## Build and run

```sh
cd launcher/src-tauri
cargo test                 # backend unit tests, no window needed
cargo run --release        # builds and starts the launcher
```

`--config <path>` or `OPEN592_LAUNCHER_CONFIG` points the launcher at a
different properties file. Without either, the file lives here:

| Platform | Default settings file |
| --- | --- |
| Windows | `launcher.properties` beside `open592-launcher.exe` |
| macOS | `~/Library/Application Support/open592/launcher.properties` |
| Linux | `$XDG_CONFIG_HOME/open592/launcher.properties`, else `~/.config/open592/launcher.properties` |

Logs go to `logs/` next to that file.

To make an installer or an app bundle, install the CLI
(`cargo install tauri-cli --version "^2"`) and run `cargo tauri build` inside
`launcher/`. Bundling is enabled in `tauri.conf.json`: on Windows this produces
an MSI/NSIS installer, on macOS an `.app` (plus DMG), and on Linux an AppImage
(plus the platform's deb/rpm packages). The `.ico`, `.icns` and PNG icons in
`src-tauri/icons` are generated by `python tools/make_icons.py` (no third-party
art), so a bundle build only needs the platform toolchain.

Platform notes: the Windows build, including its MSI/NSIS bundles, was
exercised on this machine. macOS and Linux share the same code paths (settings
directory, `java` instead of `javaw`, `open`/`xdg-open`) but need their own
machine to compile, run and bundle, since Tauri links against WebKitGTK and
WKWebView respectively.

## What the launcher does

- **Play / Stop** starts the selected jar with
  `-Xmx<512|1024|2048>m -Dsun.java2d.noddraw=true -Dopen592.config=<file> -jar <jar>`
  and owns the whole client process tree. Closing the launcher stops a client it
  started, including a Java launcher that spawns the real JVM as a child.
- **Client jar** is resolved from the settings value (relative paths are tried
  against the settings folder and the executable's folder), then discovered as
  `client-current.jar` beside the executable, beside the settings file or in up
  to four parent folders — `target/release` finds the repository jar that way.
  The **MD5** of the selected jar is shown live; **Verify** compares it with the
  expected hash.
- **Java** is auto-detected and can be overridden with Browse. The memory
  segmented control writes `memory.mb`; 2 GB needs a 64-bit runtime.
- **592HD** writes `hd.preset`: `ingame` (default) leaves `~/.open592/hd.properties`
  authoritative, and `off`/`low`/`medium`/`high`/`ultra` override it for the
  session without rewriting the player's in-game file.
- **Server & keys** writes `server.host`, `server.port`, `rsa.modulus` and
  `rsa.exponent`. The client reads those through `client.config.LaunchConfig`;
  its defaults are the stock host, port, modulus and exponent, so a client
  started without the launcher behaves exactly as before.
- **Updates** records `client.updateUrl` and `client.md5`. This build verifies a
  local jar only; the download button is a labelled placeholder.

The settings file is hand-editable. The GUI rewrites the known keys and keeps
unknown keys and comments, so a custom line survives a save; the format is
described below.

## Settings file format

`launcher.properties` is UTF-8 and uses the launcher's literal grammar, not
`java.util.Properties` escaping. The client reads the same file with the same
rules (`client.config.LauncherProperties`), so both sides always agree.

- One setting per line, `key=value` or `key:value`. The first `=` wins; if the
  line has no `=`, the first `:` separates.
- Whitespace around the line, key and value is ignored; blank lines are
  skipped.
- `#` or `!` as the first non-space character starts a comment.
- Values are literal: backslashes, `\u`, extra `=`, `:` and `#` are ordinary
  characters. A Windows path is written exactly as it is used, with no doubled
  backslashes.
- There are no escapes and no line continuations. A value cannot contain a line
  break.
- A later duplicate key replaces an earlier one. An empty value means "unset",
  so the shipped default applies.
- Unknown keys and comments are kept when the GUI saves.

Example:

```properties
# a literal Windows path, no escaping
client.jar=C:\open592\client-current.jar
java.path=C:\Program Files\Java\jre1.8.0_491\bin\javaw.exe
memory.mb=1024
hd.preset=high
server.host=play.example.com
server.port=43594
```

## Preview the UI without building the shell

`ui/mock.js` provides an in-memory backend when `window.__TAURI__` is absent:

```sh
cd launcher/ui
python -m http.server 8931
# open http://127.0.0.1:8931/
```

The status bar says `preview mode`, and nothing touches the disk.
